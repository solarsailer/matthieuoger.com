# Notes for agents

Personal site and blog of Matthieu Oger, generated by [Hugo](https://gohugo.io). It replaced a Gatsby site in November 2026, with the same URLs, content and design. Small on purpose: keep it that way.

`README.md` has the setup, the tasks (`just …`) and how posts are written. `TODOs.md` has what is open. Read both first.

## Rules

- **Posts are written by a human.** Never edit anything in `content/posts/` without asking. An approved edit goes in a commit that touches only posts, so that it can be audited.
- **No hard wrap in Markdown** (`README.md`, `TODOs.md`, this file…): one paragraph or list item per line. `just format` enforces it. Posts are never reformatted.
- **Dependencies are a decision.** Today: Hugo, Dart Sass, and for development `just`, `gotmplfmt`, Prettier and Playwright. No JavaScript library is shipped. Ask before adding anything.
- **Prefer what the platform does**: Hugo's built-in features over templates, CSS over JavaScript, plain HTML over clever code. Never post-process the HTML that Hugo generates (it was tried and rejected: it depends on Hugo's exact output).
- **No local exception**: if a rule or a tool applies, it applies everywhere (one formatter for all templates, one syntax for all quotes).
- Commit when a piece of work is done and its tests pass. Never push or deploy without being asked.
- Run `just format` and `just test` before committing.

## How it is built

- **Templates** (`layouts/`) are plain Hugo, in the current layout (`_partials`, `_markup`, `_shortcodes`). Formatted by `gotmplfmt`: tabs, as in Go. Several depend on exact whitespace (a hair space in the site title, no space between an icon and its text): the tests catch a slip.
- **Styles** (`assets/sass/`) are Sass used simply: partials, nesting, a few variables for breakpoints, one mixin. One file per component, each wrapping itself in its CSS layer; the order of layers is in `layers/order.scss`. Class names follow `block__element`. Colors are HSL and theme colors are CSS variables (`layers/theme.scss`).
- **Scripts** (`assets/js/index.js`): only the tooltips, native popovers opened and positioned by hand.
- **Formatting**: `gotmplfmt` for templates, Prettier for the rest (`.prettierignore` says what is left out). Two spaces, except templates.

## Things that are not obvious

- **Quotes with a kind** are callouts: `> [!TRANSCRIPT]`. `_markup/render-blockquote.html` turns the kind into a class. Hugo accepts any word as a kind, but no hyphen.
- **Files next to a post** are named without a path. Markdown images are resolved by Hugo's built-in hook, links by `_markup/render-link.html` (the built-in link hook rejects schemes like `shortcuts://`), and what Markdown cannot express by the `image` and `video` shortcodes. This matters because a post is also displayed on `/articles/` and in the feeds.
- **Markdown is stricter than it was with Gatsby**: footnote continuation lines need 4 spaces, a quoted paragraph needs its own `>`. The typographer is off: quotes and dashes stay as typed.
- **Lists**: Markdown wraps the text of items in paragraphs or not, depending on blank lines. Two rules in `content/list.scss` make both look the same; footnotes are excluded.
- **Feeds** are custom output formats (`hugo.toml`) with their templates (`home.atom.xml`, `home.jsonfeed.json`). Their URLs (`/atom.xml`, `/feed.json`) and the ids of their entries must never change: subscribers depend on them. The id of the feed has no trailing slash, on purpose.
- **Numbered pages of articles** are `/articles/p/2/` (`pagination.path`). An empty path looks tempting and breaks Hugo's pager links.
- **Code blocks** get their colors from a Hugo theme, generated into `layers/code-theme.scss` by `just code-theme`. Do not edit that file.
- **Posts of the same day** are in Hugo's default order. Reproducing the old order was judged not worth the code.

## Tests

`just test` builds the site and runs Playwright (`tests/`). During the migration, the reference was the production build of the Gatsby site: same URLs, same content, same feeds, same pixels, same hover states. The specs on tooltips and on the validity of the feeds stand on their own.

A failing screenshot is a question, not a verdict: look at the images in `tests/report/` before changing a test or a style.
